## Context

`README.md` 当前只有项目标题，而详细信息已经记录在 `docs/v1-technical-roadmap.md`。README 需要成为仓库入口，但不应复制整份技术路线，也不能描述当前尚不存在的构建、安装和运行流程。

## Goals / Non-Goals

**Goals:**

- 用简洁中文准确说明项目定位和 V1 目标。
- 展示已确认的技术栈与前后端边界。
- 概述核心能力和当前状态。
- 提供详细技术路线链接。

**Non-Goals:**

- 不把 README 写成完整架构设计。
- 不提供尚未验证的安装、构建或开发命令。
- 不承诺技术路线中仍标记为待确认的事项。
- 不修改应用代码或项目依赖。

## Decisions

### README 采用由概览到细节的结构

README 按“项目定位、V1 方向、技术架构、能力范围、当前状态、文档入口”组织。这样新参与者可以先快速判断项目用途，再决定是否阅读详细路线。

备选方案是直接复制技术路线摘要，但会造成内容重复和后续漂移，因此不采用。

### 明确区分后端复用与前端重建

README 明确说明只保留 Kimi Code 后端，React 前端完全重建。第一版视觉对齐 Kimi Web 仅表示设计参考，不表示复用 Vue 实现。

### 当前不加入操作命令

仓库尚未初始化 Tauri/React 应用，当前不存在可验证的安装和启动入口。README 只说明规划状态，待工程骨架落地并验证命令后再补充快速开始。

## Risks / Trade-offs

- [风险] README 与技术路线重复后发生漂移 → [控制] README 只保留稳定摘要，细节统一链接到技术路线。
- [风险] 读者误以为应用已经可运行 → [控制] 明确标记当前处于 V1 规划与工程初始化阶段。
- [风险] “样式一致”被理解成复制 Kimi Web 前端 → [控制] 明确区分视觉参考与代码复用边界。
