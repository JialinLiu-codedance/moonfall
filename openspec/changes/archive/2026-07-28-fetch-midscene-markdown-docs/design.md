## Context

`docs/midscene/llms.md` 是 Midscene 中文文档索引，目前包含 43 个指向 `./zh/...md` 的 Markdown 链接，仓库中尚无这些目标文件。源站支持在 `https://midscenejs.com/` 后拼接索引相对路径并直接返回原始 Markdown。

本次工作是一次受索引约束的内容同步，需处理嵌套目录、网络失败、路径安全及结果完整性，同时保留工作区中的无关改动。

## Goals / Non-Goals

**Goals:**

- 精确提取索引中的全部本地 Markdown 链接并去重。
- 将每个源站响应原样保存到 `docs/midscene/` 下的对应相对路径。
- 在写入前验证路径边界，在完成后验证文件集合、非空状态与 Markdown 响应特征。
- 任一下载失败时明确失败，避免把不完整镜像当作成功结果。

**Non-Goals:**

- 不递归抓取目标文档继续引用的页面或资源。
- 不转换、格式化、翻译或改写下载内容。
- 不引入长期维护的抓取程序、第三方依赖或自动定时同步。
- 不删除 `docs/midscene/` 下未被本索引引用的其他文件。

## Decisions

### 以索引链接作为唯一清单

从 Markdown 链接目标中选择以 `./` 开头且以 `.md` 结尾的路径，去重后形成下载清单。源 URL 为 `https://midscenejs.com/` 与移除前导 `./` 后的路径组合；目标路径为 `docs/midscene/` 与同一相对路径组合。

该方案确保结果与当前索引一致。被否决方案是抓取站点导航或 sitemap，因为它会扩大范围并产生索引外文件。

### 验证规范化后的目标路径边界

每个目标路径规范化后 MUST 位于 `docs/midscene/` 内，拒绝绝对路径及包含路径穿越的结果。虽然当前索引受版本控制，该约束仍能防止未来索引变化导致越界写入。

被否决方案是直接把链接字符串拼接给写文件命令，因为它没有明确限制写入边界。

### 全部下载成功后再提交目标文件

先在临时目录创建与清单一致的结构，使用会对 HTTP 错误返回非零状态的请求方式下载。全部请求成功且响应非空后，再创建目标目录并将文件移动到最终路径。

该方案将部分下载与最终镜像隔离。被否决方案是逐个直接覆盖目标文件，因为中途失败会留下新旧混合或不完整结果。

### 使用集合检查与内容检查验收

验收时重新从 `llms.md` 生成去重清单，逐项确认目标文件存在且非空，并确认本次落盘数量等于 43。抽查示例文件标题，同时检查响应未被 HTML 错误页替代。执行 `git diff --check` 及 OpenSpec 生命周期要求的验证。

仅比较文件数量不足以发现路径错配，因此采用逐路径集合检查。对源站做字节级再次下载比对会增加网络请求且易受上游即时变化影响，不作为必要验收条件。

## Risks / Trade-offs

- [源站在同步期间更新内容] → 每个文件代表各自请求时刻的内容；本次不承诺跨文件原子上游快照，并记录实际完成结果。
- [限流或短暂网络失败] → 请求设置合理超时和有限重试；仍失败则停止，不落盘临时结果。
- [HTTP 200 返回 HTML 页面] → 检查内容非空并排除明显 HTML 文档响应，抽查 Markdown 标题。
- [目标文件未来已有本地修改] → 实施前检查目标集合；若出现用户修改导致 scope 冲突，则停止并请求处理，不静默覆盖。
- [索引解析遗漏特殊 Markdown 语法] → 当前清单格式固定；实施与验收使用同一明确规则，并人工核对提取数量 43。

## Migration Plan

1. 从索引生成并校验 43 个规范化相对路径。
2. 下载至独立临时目录并完成响应校验。
3. 将临时文件移动到 `docs/midscene/zh/` 的对应路径。
4. 运行逐路径完整性检查、内容抽查和仓库检查。
5. 若需回滚，仅移除本 change 新增的 43 个目标文件及因此变空的目录；不得影响用户原有文件。
